前言

flask 模板 jinja2 框架 利用

render_template 渲染的是模板文件；render_template_string 则是把字符串直接当模板渲染

所以当代码把 render_template 换成 render_template_string、又不处理用户输入时，模板语法就会被执行，这就是 ssti 注入

类链利用原理

__class__ 返回类型所属的对象
__mro__ 返回方法解析顺序（MRO）元组，__mro__[1] 一般是 object（Python2 里 str 的 MRO 是 (str, basestring, object)，所以用 [2]）
__base__ 返回该对象直接继承的基类，等价于 __bases__[0]
__subclasses__返回基类中的所有子类，每个新类都保留了子类的引用，这个方法返回一个类中仍然可用的的引用的列表
__globals__ 是函数所在模块的全局变量字典，能从里面翻到 os、__builtins__
get_flashed_messages() 返回在Flask中通过 flash() 传入的闪现信息列表。把字符串对象表示的消息加入到一个消息队列中，然后通过调用get_flashed_messages() 方法取出(闪现信息只能取出一次，取出后闪现信息会被清空)
__builtins__ 兜底为什么万能：每个模块的 globals 里 Python 会自动塞一个 __builtins__，里面有 eval、__import__、open、chr，模块没 import os 也能现拿：

类链怎么走：__class__ → __mro__/__base__ → __subclasses__() → __init__.__globals__ → os / __builtins__

直接从函数出发

类链不是必须的：__globals__ 是函数对象的属性，模板里已经给了函数（lipsum、url_for…）时，一步就能到模块全局变量，不用 __class__ → __subclasses__() 绕一圈。

实测（flask 3.1.3 / jinja2 3.1.6）：

模板里的名字 是什么 要类链吗 __globals__ 指向 里面有什么
lipsum function 不用 jinja2.utils os、__builtins__
cycler.__init__ / joiner.__init__ / namespace.__init__ method 不用 jinja2.utils os、__builtins__
url_for function 不用 flask.app os、current_app、__builtins__
get_flashed_messages function 不用 flask.helpers os、__builtins__
self TemplateReference 对象 只用一层 .__init__ jinja2.runtime 没有 os，有 __builtins__
config Config 实例 只用一层 .__class__.__init__ flask.config 配置项
''、[]、()、{} 字符串/列表等 必须 无（本身不是函数） 只能 __subclasses__()
request 对象 一层 .__application.__globals__ flask.app __builtins__

盲注

实在送不出去（不出网、没静态目录、header 也被挡），只能一位一位地猜：

  • 布尔盲注：用条件语句，让”条件真/假”对应页面内容或状态码不同
  • 时间盲注：条件为真时才执行 sleep，看响应时间
  • 带外：结果通过 DNS/HTTP 打出去（适合有出网但没回显）

实测（把 sleep 换成 Python 版给 Windows 测的）：条件真 1.58s、条件假 0.01s ✓；注意 sleep 是 Linux 命令，Windows 靶场要换 ping -n 3 127.0.0.1 之类
